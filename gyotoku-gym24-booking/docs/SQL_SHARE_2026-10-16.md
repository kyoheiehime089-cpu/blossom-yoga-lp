# Manual Booking Rules: CANDIDATE ONLY

This feature branch is NOT the production release. Do not merge/deploy yet.
It supersedes the earlier consent-linked draft, which was never committed.
Production SQL is executed only by the designated cloud operator.

## Fixed Workflow

1. Existing independent consent form submission and its existing emails stay unchanged.
2. Owner performs identity checks.
3. Owner manually registers a member and chooses Light/Standard/Premium in the booking admin app.
4. Owner copies the login details and sends them through official LINE manually.
5. Member books under the explicitly assigned plan and current rules.

No consent record ID, consent DB lookup, automatic member synchronization,
payment API, new Vercel environment variables or LINE auto-delivery is required.

## Current Candidate

- Core schema/RPC: `../supabase-manual-plan-rules-candidate.sql`.
- Guarded atomic SQL: `production-atomic-admin-manual-plan-transaction.sql`.
- Manual member creation: `fs_v7_admin_create_member(text,text,text,text)`.
- Manual plan/status change: `fs_v7_admin_update_plan(text,uuid,text,text)`.
- Existing member plans/overrides/history are not automatically migrated.
- New members carry an explicit local rule assignment. No email matching converts an old account.
- Public consent/API/email source is outside this release and unchanged.
- The old 76,068-byte `production-atomic-admin-v7-transaction.sql` is obsolete. Do not execute it.

The atomic SQL still fails closed on missing owner/admin verification, catalog
or fingerprint drift, unsafe old administrative routes or changed old rows.
Keep only the access protection required for reservation/member management.
No new MFA, dashboard/organization access, secret entry or consent-store permission
is granted. Existing public legacy-passcode weaknesses must not be copied into
new sensitive RPCs. The already installed helper/buffer are not reapplied.
